# Agent guide

The real application is `src/agent.ts`, invoked by `src/cli.ts`. It uses `@anthropic-ai/claude-agent-sdk` with the synthetic target MCP tools. `src/mcp-tools.ts` defines the operation subset shared by `src/mcp-server.ts` (stdio) and `src/http-server.ts` (HTTP); `src/mailbox.ts` persists one synthetic JSON mailbox state file. `src/connection.ts` validates the selected transport and reads remote status.

- Build with Node.js 20.19+ using `npm ci && npm run build`.
- Offline proof: `npm run check`. Its 35 tests cover state effects, actual MCP stdio/HTTP traffic and the actual Agent SDK protocol over a synthetic child. No provider call or real Claude model loop is exercised.
- Normal task: `npm run mailbox -- list` then `npm run mailbox -- init --case starter-mailbox --state run-output/mailbox.json`, then set `ANTHROPIC_API_KEY` and run `npm run mailbox -- ask --state run-output/mailbox.json --request "Find the October invoice"`.
- Configuration: `AGENT_MODEL` or `--model` selects Claude; `--allow-send` and `--allow-label` authorize those write operations for that invocation. A request ID can be fixed with `--request-id` to make retries idempotent. The send permission callback requires that exact caller ID; do not let model-created IDs bypass retry safety.
- Dependency boundary: choose exactly one of `--state` for an owned stdio child process or `--mcp-url` for caller-owned HTTP MCP. Both implement status, search, get, label and synthetic send; neither connects to Gmail. `--state` must be marked `synthetic: true`. HTTP requires `MAILBOX_MCP_TOKEN` (32+ random non-whitespace characters); the URL must use HTTPS outside loopback and cannot include credentials/query/fragment. A failed remote preflight stops before the model, with no fallback.
- HTTP service: `npm run mailbox -- serve --state run-output/mailbox.json --port 8787` emits ready JSON without the token, binds loopback, and exits cleanly on SIGINT/SIGTERM. The caller owns the service, state path and any remote TLS proxy. Write tools are absent unless the server starts with `--allow-send` or `--allow-label`; the agent invocation must independently authorize them. No OAuth or hosted-deployment proof is claimed.
- Dataset: `northstar-mailbox` 1.0.0 has six digest-bound snapshots/four profiles, including a 24-message busy mailbox, unresolved evidence and historical completed work. `datasets.ts` verifies digests/identities and rejects path escapes. Listing makes no model call. Reproduce with `node scripts/make-fixtures.mjs`; change dataset version when qualifying input changes. Custom `--seed` data is validated but not manifest-certified.
- State/reset: use `init --case` to copy exact verified bytes into a new private state file with exclusive creation. Each case path is owned by its invocation; do not run two writers against one path. The CLI does not reset or delete files automatically.
- Completion: one success result with explicit `is_error=false`, nonblank answer and no pending/deferred/known unfinished stop. API errors inside a success subtype are failures. Bounds: 12 turns, three-minute abort, SDK USD 1 estimated-budget threshold (not a billing cap). Always close Query; session persistence is disabled and its empty temporary cwd is removed. No settings or built-in tools are loaded.
- Failure: JSON stderr/no success stdout, retaining available raw SDK result and initial/final status hashes. A state-read failure stays explicit/null and must not erase model evidence or imply rollback. Inspect audit and preserve caller request ID on a send retry.
- Evidence: final answer, request/prompt/state hashes, declared dataset identity and raw SDK result with session/usage/per-model totals/permission denials. SDK cost is an estimate; missing usage is unknown, never zero billing. Do not sum cumulative modelUsage with main-loop usage. Current state hash must be compared with seed manifest if claiming pristine reset. No live model result exists yet.
- Keep provider credentials out of target MCP and Git. Do not present this subset as full Gmail compatibility or use old Firedrill drills. A new Firedrill connection remains pending verification of the released interface.
